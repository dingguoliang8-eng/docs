LangGraph lets you build agent workflows as **explicit, stateful graphs** — a step beyond simple LLM chains. Where LangChain's LCEL chains are acyclic (input flows forward to output), LangGraph supports **cycles**: a node can route execution back to an earlier node, enabling the iterative loops that agents require. Built on top of LangChain, it gives you typed shared state, deterministic control flow, and first-class support for human-in-the-loop interrupts and long-term persistence.

<Tip>
  If your workflow is a straight pipeline — prompt in, structured output — use LCEL. Reach for LangGraph the moment you need loops, branching, or state that persists across multiple LLM calls.
</Tip>

## Core Concepts

### StateGraph

`StateGraph` is the central object in every LangGraph application. You define it with a **typed state schema** — a `TypedDict` that describes every field your graph reads and writes. All nodes share this schema; when a node returns a dict, LangGraph merges it into the current state using each field's **reducer** function.

```python agents/state_schema.py
from typing import TypedDict, Annotated
from langgraph.graph.message import add_messages

class AgentState(TypedDict):
    # add_messages is a reducer: it appends new messages rather than replacing
    messages: Annotated[list, add_messages]
    # Simple fields are replaced on each update
    current_step: str
    error_count: int
```

<Note>
  The `add_messages` reducer is a LangGraph built-in that appends incoming messages to the list rather than overwriting it. For any field where you want replacement semantics (the default), omit the `Annotated` wrapper.
</Note>

### Nodes

A **node** is any Python callable that accepts the current state and returns a partial state update. Nodes are where your LLM calls, tool executions, and business logic live.

```python agents/nodes.py
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o", temperature=0)

def call_llm(state: AgentState) -> dict:
    """Invoke the LLM with the current message history."""
    response = llm.invoke(state["messages"])
    return {"messages": [response]}

def handle_error(state: AgentState) -> dict:
    """Increment the error counter and add a recovery message."""
    return {"error_count": state["error_count"] + 1}
```

### Edges

**Edges** define the control flow between nodes. LangGraph supports two kinds:

- **Normal edges** (`add_edge`): unconditional transitions. After node A, always go to node B.
- **Conditional edges** (`add_conditional_edges`): a routing function inspects state and returns the name of the next node (or `END`).

```python agents/edges.py
from langgraph.graph import END

def should_continue(state: AgentState) -> str:
    """Route to 'tools' if the LLM made a tool call, otherwise finish."""
    last_message = state["messages"][-1]
    if hasattr(last_message, "tool_calls") and last_message.tool_calls:
        return "tools"
    return END
```

### Checkpointing

A **checkpointer** persists the full graph state after every node execution. This enables:

- **Resumption**: pick up a long-running task exactly where it left off.
- **Human-in-the-loop**: pause the graph, wait for a user decision, then resume.
- **Time-travel debugging**: replay the graph from any historical state.

```python agents/checkpointing.py
from langgraph.checkpoint.memory import MemorySaver
from langgraph.checkpoint.sqlite import SqliteSaver

# In-memory: great for development and testing
memory = MemorySaver()
graph = builder.compile(checkpointer=memory)

# SQLite: persistent across process restarts.
# from_conn_string is a context manager — always use it with `with`.
with SqliteSaver.from_conn_string("checkpoints.db") as db:
    persistent_graph = builder.compile(checkpointer=db)
    result = persistent_graph.invoke(
        {"messages": [HumanMessage(content="Hello")]},
        config={"configurable": {"thread_id": "session-1"}},
    )
```

<Warning>
  `MemorySaver` is lost when your process exits. Use `SqliteSaver` (local) or a production-grade checkpointer (PostgreSQL via `langgraph-checkpoint-postgres`) for any workflow that needs to survive restarts or serve multiple users concurrently. Note that `SqliteSaver.from_conn_string` is a **context manager** — passing it without `with` returns a generator object, not a checkpointer, causing a runtime error.
</Warning>

## Building Your First Agent

Here's a complete ReAct-style agent built with LangGraph. Follow the steps, then review the full code below.

<Steps>
  <Step title="Define the state schema">
    Create a `TypedDict` with every field your graph needs. For a message-based agent, `messages` with the `add_messages` reducer is almost always your starting point.

    ```python agents/react_agent.py
    from typing import TypedDict, Annotated
    from langgraph.graph.message import add_messages

    class AgentState(TypedDict):
        messages: Annotated[list, add_messages]
    ```
  </Step>

  <Step title="Create the LLM and tool nodes">
    Bind your tools to the LLM so it knows how to call them. The `ToolNode` from LangGraph handles executing tool calls and returning `ToolMessage` objects automatically.

    ```python agents/react_agent.py
    from langchain_openai import ChatOpenAI
    from langchain_community.tools.tavily_search import TavilySearchResults
    from langgraph.prebuilt import ToolNode

    llm = ChatOpenAI(model="gpt-4o", temperature=0)
    tools = [TavilySearchResults(max_results=3)]

    llm_with_tools = llm.bind_tools(tools)
    tool_node = ToolNode(tools)

    def call_llm(state: AgentState) -> dict:
        response = llm_with_tools.invoke(state["messages"])
        return {"messages": [response]}
    ```
  </Step>

  <Step title="Add nodes and edges with conditional routing">
    Wire up the graph: START → LLM → (tools → LLM again) or END.

    ```python agents/react_agent.py
    from langgraph.graph import StateGraph, START, END

    def should_continue(state: AgentState) -> str:
        last = state["messages"][-1]
        if hasattr(last, "tool_calls") and last.tool_calls:
            return "tools"
        return END

    builder = StateGraph(AgentState)
    builder.add_node("llm", call_llm)
    builder.add_node("tools", tool_node)

    builder.add_edge(START, "llm")
    builder.add_conditional_edges("llm", should_continue)
    builder.add_edge("tools", "llm")  # after tools, always go back to LLM
    ```
  </Step>

  <Step title="Compile and invoke the graph">
    Compile with an optional checkpointer, then invoke with a thread ID so state is tracked per conversation.

    ```python agents/react_agent.py
    from langgraph.checkpoint.memory import MemorySaver
    from langchain_core.messages import HumanMessage

    graph = builder.compile(checkpointer=MemorySaver())

    config = {"configurable": {"thread_id": "session-001"}}
    result = graph.invoke(
        {"messages": [HumanMessage(content="What's the weather in Tokyo right now?")]},
        config=config,
    )
    print(result["messages"][-1].content)
    ```
  </Step>
</Steps>

### Complete Agent Code

<CodeGroup>
```python agents/react_agent.py
from typing import TypedDict, Annotated
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langgraph.prebuilt import ToolNode
from langgraph.checkpoint.memory import MemorySaver
from langchain_openai import ChatOpenAI
from langchain_community.tools.tavily_search import TavilySearchResults
from langchain_core.messages import HumanMessage

# ── State ──────────────────────────────────────────────────────────────────
class AgentState(TypedDict):
    messages: Annotated[list, add_messages]

# ── LLM + Tools ───────────────────────────────────────────────────────────
llm = ChatOpenAI(model="gpt-4o", temperature=0)
tools = [TavilySearchResults(max_results=3)]
llm_with_tools = llm.bind_tools(tools)
tool_node = ToolNode(tools)

# ── Nodes ─────────────────────────────────────────────────────────────────
def call_llm(state: AgentState) -> dict:
    response = llm_with_tools.invoke(state["messages"])
    return {"messages": [response]}

# ── Routing ───────────────────────────────────────────────────────────────
def should_continue(state: AgentState) -> str:
    last = state["messages"][-1]
    if hasattr(last, "tool_calls") and last.tool_calls:
        return "tools"
    return END

# ── Graph ─────────────────────────────────────────────────────────────────
builder = StateGraph(AgentState)
builder.add_node("llm", call_llm)
builder.add_node("tools", tool_node)
builder.add_edge(START, "llm")
builder.add_conditional_edges("llm", should_continue)
builder.add_edge("tools", "llm")

graph = builder.compile(checkpointer=MemorySaver())

# ── Invocation ────────────────────────────────────────────────────────────
if __name__ == "__main__":
    config = {"configurable": {"thread_id": "demo-thread"}}
    result = graph.invoke(
        {"messages": [HumanMessage(content="Research the latest LangGraph release.")]},
        config=config,
    )
    print(result["messages"][-1].content)
```

## Human-in-the-Loop

LangGraph's interrupt mechanism lets you **pause** graph execution before or after any node, surface the current state to a human, and then resume with updated input.

```python agents/human_in_loop.py
from langgraph.checkpoint.sqlite import SqliteSaver
from langchain_core.messages import HumanMessage

# SqliteSaver.from_conn_string is a context manager — use it with `with`
with SqliteSaver.from_conn_string("hitl.db") as db:
    # Interrupt BEFORE the "tools" node runs — let a human approve the tool call
    hitl_graph = builder.compile(
        checkpointer=db,
        interrupt_before=["tools"],
    )

    config = {"configurable": {"thread_id": "hitl-session-1"}}

    # Run until the interrupt
    state = hitl_graph.invoke(
        {"messages": [HumanMessage(content="Delete all files in /tmp")]},
        config=config,
    )

    # Inspect pending tool calls
    pending = state["messages"][-1].tool_calls
    print("Pending tool calls:", pending)

    # Human approves → resume by passing None (no state change needed)
    final = hitl_graph.invoke(None, config=config)
    print(final["messages"][-1].content)
```

<Tip>
  Use `interrupt_before` to gate destructive or irreversible actions (file writes, API mutations, email sends). Use `interrupt_after` when you want to review the tool result before the LLM reasons about it.
</Tip>

## Streaming

LangGraph supports three streaming modes, letting you push incremental output to your UI as soon as it's available.

<CodeGroup>
```python agents/streaming_values.py
# stream_mode="values" — emit full state after every node
for state in graph.stream(
    {"messages": [HumanMessage(content="Explain quantum entanglement")]},
    config=config,
    stream_mode="values",
):
    last = state["messages"][-1]
    print(f"[{last.__class__.__name__}] {last.content[:80]}")
```

```python agents/streaming_updates.py
# stream_mode="updates" — emit only the delta returned by each node
for node_name, update in graph.stream(
    {"messages": [HumanMessage(content="Explain quantum entanglement")]},
    config=config,
    stream_mode="updates",
):
    print(f"Node '{node_name}' updated: {list(update.keys())}")
```

```python agents/streaming_tokens.py
# astream_events — stream individual LLM tokens for real-time display
import asyncio

async def stream_tokens():
    async for event in graph.astream_events(
        {"messages": [HumanMessage(content="Write a haiku about agents")]},
        config=config,
        version="v2",
    ):
        if event["event"] == "on_chat_model_stream":
            chunk = event["data"]["chunk"].content
            if chunk:
                print(chunk, end="", flush=True)

asyncio.run(stream_tokens())
```
</CodeGroup>

<Warning>
  `stream_mode="debug"` emits every internal LangGraph event including checkpoint reads and writes. It's invaluable for debugging but extremely verbose — disable it before going to production or your logs will be unmanageable.
</Warning>
