AI Agent 靠大模型驱动，在 **感知 → 规划 → 行动** 的循环里干活。它不是答完一轮就停，而是根据用户输入、工具结果和记忆决定下一步，调用工具或委派子 Agent，改状态，再继续——直到达成目标或触发终止条件。静态「提示—回答」做不到这种能力。

## Agent 由什么组成？

能上线的 Agent，通常由这几块拼起来：

| 组件 | 作用 |
| --- | --- |
| **LLM 骨干** | 推理引擎。根据当前上下文决定下一步做什么。 |
| **工具 / 函数** | LLM 可调用的外部能力：网页搜索、代码执行、API 调用、数据库查询。 |
| **短期记忆** | 活跃上下文窗口——当前运行中累积的消息、工具结果与观察。 |
| **长期记忆** | 跨运行的持久存储：向量库、数据库或 Agent 可读写的键值缓存。 |
| **规划策略** | Agent 如何分解目标：ReAct、plan-and-execute、tree-of-thought 等。 |
| **执行循环** | 保持 Agent 运行直到满足停止条件的控制流。 |

<Note>
  短期记忆受模型上下文窗口限制。若任务需要追踪大量工具结果或很长对话历史，需要在触顶前设计长期记忆策略——语义检索、摘要或结构化状态。
</Note>

### 执行循环

在代码层面，每个 Agent 循环大致如下：

```python agents/core_loop.py
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

llm = ChatOpenAI(model="gpt-4o", temperature=0)
tools = [search_web, run_python]  # 你的工具函数
llm_with_tools = llm.bind_tools(tools)

def run_agent(user_input: str, max_steps: int = 10):
    messages = [HumanMessage(content=user_input)]

    for step in range(max_steps):
        response = llm_with_tools.invoke(messages)
        messages.append(response)

        # 没有工具调用 → Agent 完成
        if not response.tool_calls:
            return response.content

        # 执行每个工具调用并把结果喂回
        for tool_call in response.tool_calls:
            result = execute_tool(tool_call)
            messages.append(result)

    return "已达最大步数，仍未给出最终答案。"
```

<Tip>
  务必设置 `max_steps` 护栏。没有它，困惑或陷入循环的 Agent 会无限运行并烧光 Token。多数任务以 10 步为合理默认；只有在确有必要时再提高。
</Tip>

## Agent 架构

没有一种架构适合所有问题。下面是最常见的三种模式，以及各自值得增加复杂度的场景。

### 1. ReAct（推理 \+ 行动）

ReAct 在紧密循环中交错**思考**与**行动**。每一步模型产生 `Thought`（内部推理），然后是 `Action`（工具调用或最终答案），再观察结果后决定下一步。

- **优势：** 实现简单、高度透明（推理轨迹可读）、对意外结果适应自然。
- **劣势：** 可能陷入推理循环；缺少事先规划时，多步骤任务可能走低效路径。

```python agents/react_loop.py
# 基于 LangChain 的最小 ReAct 循环
from langchain import hub
from langchain.agents import create_react_agent, AgentExecutor
from langchain_openai import ChatOpenAI
from langchain_community.tools.tavily_search import TavilySearchResults

llm = ChatOpenAI(model="gpt-4o", temperature=0)
tools = [TavilySearchResults(max_results=3)]

# 从 LangChain Hub 拉取标准 ReAct 提示
prompt = hub.pull("hwchase17/react")

agent = create_react_agent(llm, tools, prompt)
executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

result = executor.invoke({"input": "What is the current price of Bitcoin?"})
print(result["output"])
```

### 2. Plan-and-Execute

Agent 先生成**完整计划**（编号步骤列表），再按序执行每一步——执行阶段常用更轻量的模型。若某步失败或新信息改变策略，可由 replanner 修订计划。

- **优势：** 在复杂多步骤任务上更高效；计划在执行前显式可见，更易审计。
- **劣势：** 早期假设出错时较脆弱；需要重规划机制才能优雅恢复。

### 3. Reflection / Self-Critique

产出初稿后，Agent 调用**批评**步骤——同一模型换提示，或单独模型——评估质量并找出缺口，再据此修订。循环直到输出达到质量阈值或触及最大修订次数。

- **优势：** 对有明确成功标准的任务（代码正确性、事实准确性、写作质量）显著提升输出质量。
- **劣势：** 延迟翻倍或三倍；批评提示必须精心设计，否则 Agent 会「一律通过」。

## 如何选择架构

可作快速决策参考：

| 场景 | 推荐模式 |
| --- | --- |
| 开放式研究或工具使用不可预测的问答 | **ReAct** |
| 有已知子步骤的长结构化任务（如报告生成） | **Plan-and-Execute** |
| 高质量比速度更重要的高风险输出 | **Reflection** |
| 有专用子任务的复杂工作流 | **多智能体**（见下文） |

<Note>
  从 ReAct 起步。它最易调试，多数真实 Agent 任务并不需要规划或反思的额外开销。只有在识别出更简单架构无法处理的具体失败模式时，再增加复杂度。
</Note>
