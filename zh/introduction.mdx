这个知识库面向构建、部署与扩展生产级 LLM 系统的工程师。无论你是在设计 Agent 工作流的 AI 工程师、把 LLM API 接入 SaaS 的后端工程师、评估工程深度的技术招聘方，还是探索架构模式的 LLM 开发者——这里都有基于真实项目、偏实践的内容。

范围覆盖现代 AI 工程的主要面：**基于 LangGraph 的 AI Agent 架构与多智能体编排**、**检索增强生成（RAG）流水线与嵌入策略**、**基于 vLLM 与云推理的 LLM 部署与基础设施**、**ASR/TTS 语音 AI**，以及融合视觉、音频与语言的**多模态系统**。目标不是罗列所有工具，而是记录在生产环境中真正管用的做法。

## 核心工程理念

本知识库中描述的系统遵循四条原则：

**1. 生产优先** 每个架构决策都先对照生产约束——延迟预算、每 Token 成本、负载下的失败模式、可观测性要求。Demo 与原型有助于探索，但门槛始终是：「这能扛住生产吗？」

**2. 可组合架构** 难以扩展或替换的 LLM 系统很快会变成负担。更倾向模块化、可组合设计——检索与生成分离、Agent 逻辑与工具实现解耦——以便在模型格局变化时独立升级组件。

**3. 可观测性是一等公民** 链路追踪、结构化日志与评估体系不是事后补丁。从第一天就对 LLM 调用、Agent 步骤与检索质量做埋点，才能把系统从「只能重启」变成「可以持续改进」。

**4. 迭代改进，而非推倒重来** LLM 系统质量靠度量与小步、有针对性的改动提升。尽早建立评估基线，再迭代提示词、分块策略、检索参数或模型选择，能在不引入回退的情况下形成复利收益。
