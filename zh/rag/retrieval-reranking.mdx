检索质量往往是 RAG 最大的瓶颈。上下文烂，再强的模型也编不出靠谱答案。常见两类失败：**根本没召回对的文档**（recall），以及**塞了一堆噪声/重复上下文**（precision）。

## 检索策略

### 1. Dense（向量相似度）

查询和文档都做 Embedding，取最近邻。语义近、改写也能匹配。

**弱点：** 产品码、版本号、专有名词等精确词容易漂。

### 2. Sparse（BM25 / 关键词）

经典词频排序，精确匹配强。

**弱点：** 「汽车」和「car」对它是两回事。

### 3. 混合检索 \+ RRF

Dense 和 Sparse 并行，再用 Reciprocal Rank Fusion 合并列表。生产里几乎总是比纯 dense 稳——Sparse 给精确词兜底。

```python title="hybrid_retrieval.py"
from langchain.retrievers import EnsembleRetriever
from langchain_community.retrievers import BM25Retriever

dense_retriever = vectorstore.as_retriever(search_kwargs={"k": 20})
bm25_retriever = BM25Retriever.from_documents(chunks, k=20)

hybrid_retriever = EnsembleRetriever(
    retrievers=[bm25_retriever, dense_retriever],
    weights=[0.4, 0.6]
)
results = hybrid_retriever.invoke("What is the refund policy for digital goods?")
```

## 重排（Reranking）

一阶段追求召回（取 20–50 条候选），重排追求精度（压到 3–5 条给 LLM）。

Cross-encoder 把「查询 \+ 文档」成对打分，比 bi-encoder 准，但更贵——所以只在候选集上跑。

可选 Cohere Rerank（托管）或 BGE Reranker（自托管）。

<Warning>
  给 LLM 塞 10\+ 块往往反而更差（「lost in the middle」）。3–5 块高质量上下文，通常好过一堆凑数的。
</Warning>

## MMR：控制冗余

Top 结果都来自同一段落时，上下文窗口在浪费。MMR 在相关性和多样性之间折中，用 `lambda_mult` 调（偏相关或偏覆盖）。

## 怎么评估

先测再优化：Hit Rate / Recall@K、MRR、NDCG、Context Precision/Recall。可用 RAGAs 做自动化评估；改流水线前后用同一批 50–100 题对比。
