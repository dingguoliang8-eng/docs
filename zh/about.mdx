## 工程背景

我的实战经验覆盖现代 AI 应用开发的核心方向：

**LLM 应用开发** 基于 OpenAI GPT-4 与 Anthropic Claude 系列构建生产应用，处理大规模场景下的提示工程、结构化输出解析、Function Calling 与上下文窗口管理。也深度使用开源模型——Llama、Mistral、Qwen——覆盖微调与直接推理，对闭源与开源权重模型的能力与成本权衡有落地理解。

**RAG 流水线设计与优化** 从零设计并迭代检索增强生成流水线——从文档摄入与分块策略，到嵌入模型选型、向量库索引、混合检索配置与检索评估。清楚朴素 RAG 在生产中何处失效，以及如何用重排、查询变换与上下文压缩应对。

**LangGraph Agent 工作流** 用 LangGraph 构建有状态、多步骤 Agent 工作流，包括工具调用 Agent、反思循环，以及带专用子图节点的多智能体系统。处理过 Agent 可靠性的实际挑战：优雅处理工具失败、管理长时状态、设计人机协同检查点。

**LLM 部署与推理** 用 vLLM 与 Ollama 部署并管理自托管 LLM 推理栈，在不同硬件配置下调吞吐与延迟。也使用过云托管推理端点，理解成本、延迟、控制力与合规等驱动「自托管 vs 托管服务」的运营权衡。

**多租户架构的 AI SaaS 产品** 参与并主导过把租户隔离、用量计量、按租户模型配置作为一等需求的 AI SaaS 产品。这意味着理解 LLM 能力如何与底层 SaaS 平台交互：API 网关、限流、计费钩子与审计日志。

**语音 AI（ASR 与 TTS）** 集成并部署过基于 OpenAI Whisper（含低延迟场景的 faster-whisper 变体）的自动语音识别，以及 CosyVoice、FishSpeech 的文本转语音。构建过端到端语音流水线——音频输入、转写、LLM 处理、合成语音输出——覆盖批处理与流式场景。

## 正在走向哪里

目标是从 AI 应用工程走向 **AI Agent 工程**，最终走向 **AI Runtime 工程**。

对我而言，这个区分很重要。AI 应用工程是把模型能力集成进软件产品。Agent 工程是设计能在更长时域中推理、规划并自主行动的系统——能从失败中恢复、协调子 Agent、管理长时状态，并通过工具与 API 与世界交互。AI Runtime 工程再下一层：构建 Agent 系统所依赖的执行环境、调度基础设施与框架。

具体而言，我正朝着这些方向努力：

- 设计并部署能在生产环境中处理复杂、开放式任务的**自主多智能体系统**
- 为**开源 Agent 框架**做贡献——尤其在状态管理、工具执行与 Agent 评估方面
- 构建并实验超越当前框架能力暴露面的 **Agent Runtime 与编排层**
- 发展严谨的 **Agent 评估方法**：如何度量在真实世界中行动的系统的能力、可靠性与安全性？

## 为什么做这个作品集

多数 AI 工程知识散落在 GitHub README、博客与 Discord 里。我建这个知识库，是因为需要一个结构化的地方，沉淀真实项目中学到的东西——架构决策、失败模式、基准数字，以及文档里并不显而易见的权衡理由。

它也是一种约束装置。把系统写清楚，会逼出比「只是做出来」更强的精确性。如果我无法清楚解释检索流水线为何这样分块，或为何选某种 Agent 图拓扑而非另一种，那我大概还理解得不够深。

本作品集是活文档。随构建、学习与修正理解而增长。目标不是面面俱到——而是诚实记录我知道什么、如何知道，以及知识边界在哪里。
