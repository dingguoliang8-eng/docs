AI agents are LLM-powered systems that operate in a continuous **perception → planning → action** loop. Rather than responding to a single prompt and stopping, an agent perceives its environment (user input, tool results, memory), plans what to do next, executes actions (tool calls, sub-agent delegation, state updates), and repeats — until it reaches a goal or termination condition. This architecture unlocks capabilities that static prompt-response systems simply cannot achieve.

## What Makes an Agent?

Every reliable agent is built from a small set of composable components. Understanding what each one does — and how they interact — is the foundation for designing systems that actually work in production.

| Component | Role |
|---|---|
| **LLM Backbone** | The reasoning engine. Decides what to do next based on current context. |
| **Tools / Functions** | External capabilities the LLM can invoke: web search, code execution, API calls, database lookups. |
| **Short-Term Memory** | The active context window — messages, tool results, and observations accumulated in the current run. |
| **Long-Term Memory** | Persistent storage across runs: vector stores, databases, or key-value caches the agent can read and write. |
| **Planning Strategy** | How the agent decomposes goals: ReAct, plan-and-execute, tree-of-thought, etc. |
| **Execution Loop** | The control flow that keeps the agent running until a stop condition is met. |

<Note>
  Short-term memory is bounded by the model's context window. For tasks that require tracking many tool results or long conversation histories, you'll need a long-term memory strategy — semantic retrieval, summarization, or structured state — before you hit the limit.
</Note>

### The Execution Loop

At the code level, every agent loop looks roughly like this:

```python agents/core_loop.py
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage

llm = ChatOpenAI(model="gpt-4o", temperature=0)
tools = [search_web, run_python]  # your tool functions
llm_with_tools = llm.bind_tools(tools)

def run_agent(user_input: str, max_steps: int = 10):
    messages = [HumanMessage(content=user_input)]

    for step in range(max_steps):
        response = llm_with_tools.invoke(messages)
        messages.append(response)

        # No tool calls → agent is done
        if not response.tool_calls:
            return response.content

        # Execute each tool call and feed results back
        for tool_call in response.tool_calls:
            result = execute_tool(tool_call)
            messages.append(result)

    return "Max steps reached without a final answer."
```

<Tip>
  Always set a `max_steps` guard. Without it, a confused or looping agent will run indefinitely and burn through tokens. Ten steps is a reasonable default for most tasks; increase it only when you have a compelling reason.
</Tip>

## Agent Architectures

No single architecture fits every problem. Here are the three patterns you'll encounter most often, along with when each one earns its complexity.

### 1. ReAct (Reasoning + Acting)

ReAct interleaves **thinking** and **acting** in a tight loop. On each step the model produces a `Thought` (internal reasoning), then an `Action` (tool call or final answer), then observes the result before deciding what to do next.

- **Strengths:** Simple to implement, highly transparent (the reasoning trace is readable), adapts naturally to unexpected results.
- **Weaknesses:** Can get stuck in reasoning loops; the lack of upfront planning means it may take inefficient paths on multi-step tasks.

```python agents/react_loop.py
# Minimal ReAct loop with LangChain
from langchain import hub
from langchain.agents import create_react_agent, AgentExecutor
from langchain_openai import ChatOpenAI
from langchain_community.tools.tavily_search import TavilySearchResults

llm = ChatOpenAI(model="gpt-4o", temperature=0)
tools = [TavilySearchResults(max_results=3)]

# Pull the standard ReAct prompt from LangChain Hub
prompt = hub.pull("hwchase17/react")

agent = create_react_agent(llm, tools, prompt)
executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

result = executor.invoke({"input": "What is the current price of Bitcoin?"})
print(result["output"])
```

### 2. Plan-and-Execute

The agent first generates a **complete plan** (a numbered list of steps), then executes each step sequentially — often using a separate, lighter model for execution. A replanner can revise the plan if a step fails or new information changes the strategy.

- **Strengths:** Efficient on complex, multi-step tasks; easier to audit because the plan is explicit before execution begins.
- **Weaknesses:** Brittle if early assumptions prove wrong; requires a replanning mechanism to recover gracefully.

### 3. Reflection / Self-Critique

After producing an initial output, the agent invokes a **critic** step — either the same model with a different prompt, or a separate model — to evaluate quality and identify gaps. The output is then revised based on the critique. This loop repeats until the output meets a quality threshold or a max-revision limit is hit.

- **Strengths:** Substantially improves output quality for tasks with well-defined success criteria (code correctness, factual accuracy, writing quality).
- **Weaknesses:** Doubles or triples latency; the critic prompt must be carefully designed or the agent will approve everything.

## Choosing the Right Architecture

Use this as a quick decision guide:

| Scenario | Recommended Pattern |
|---|---|
| Open-ended research or Q&A with unpredictable tool use | **ReAct** |
| Long, structured tasks with known sub-steps (e.g., report generation) | **Plan-and-Execute** |
| High-stakes outputs where quality matters more than speed | **Reflection** |
| Complex workflows with specialized sub-tasks | **Multi-Agent** (see below) |

<Note>
  Start with ReAct. It's the simplest pattern to debug, and most real-world agent tasks don't need the overhead of planning or reflection. Add complexity only when you've identified a concrete failure mode that simpler architectures can't handle.
</Note>
