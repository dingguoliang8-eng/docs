## Engineering Background

My hands-on experience covers the core disciplines of modern AI application development:

**LLM Application Development**
I have built production applications on top of OpenAI GPT-4 and the Anthropic Claude family, handling prompt engineering, structured output parsing, function calling, and context window management at scale. I have also worked extensively with open-source models — Llama, Mistral, and Qwen — in both fine-tuning and direct inference contexts, which gives me a grounded understanding of the capability and cost trade-offs between proprietary and open-weight models.

**RAG Pipeline Design and Optimisation**
I have designed and iterated on retrieval-augmented generation pipelines from the ground up — from document ingestion and chunking strategy through embedding model selection, vector store indexing, hybrid search configuration, and retrieval evaluation. I have learned where naive RAG breaks down in production and how to address it with re-ranking, query transformation, and contextual compression.

**LangGraph Agent Workflows**
I have built stateful, multi-step agent workflows using LangGraph, including tool-use agents, reflection loops, and multi-agent systems with specialised subgraph nodes. I have navigated the practical challenges of agent reliability: handling tool failures gracefully, managing long-running state, and designing human-in-the-loop checkpoints.

**LLM Deployment and Inference**
I have deployed and managed self-hosted LLM inference stacks using vLLM and Ollama, tuning for throughput and latency across different hardware configurations. I have also worked with cloud-managed inference endpoints and understand the operational trade-offs — cost, latency, control, and compliance — that drive the decision between self-hosted and managed serving.

**AI SaaS Products with Multi-Tenant Architecture**
I have contributed to and led development on AI SaaS products where tenant isolation, usage metering, and per-tenant model configuration are first-class requirements. This means understanding how LLM features interact with the underlying SaaS platform: API gateways, rate limiting, billing hooks, and audit logging.

**Speech AI (ASR and TTS)**
I have integrated and deployed automatic speech recognition using OpenAI Whisper (including faster-whisper variants for low-latency use cases) and text-to-speech using CosyVoice and FishSpeech. I have built end-to-end voice pipelines — audio input, transcription, LLM processing, and synthesised speech output — for both batch and streaming scenarios.

## What I'm Building Toward

My goal is to move from AI Application Engineering into **AI Agent Engineering** and ultimately **AI Runtime Engineering**.

The distinction matters to me. AI application engineering is about integrating model capabilities into software products. Agent engineering is about designing systems that reason, plan, and act autonomously across extended time horizons — systems that can recover from failures, coordinate sub-agents, manage long-running state, and interact with the world through tools and APIs. AI runtime engineering goes a level deeper still: building the execution environments, scheduling infrastructure, and frameworks that agent systems run on top of.

Concretely, I am working toward:

- Designing and deploying **autonomous multi-agent systems** capable of handling complex, open-ended tasks in production environments
- Contributing to **open-source agent frameworks** — particularly in areas of state management, tool execution, and agent evaluation
- Building and experimenting with **agent runtimes and orchestration layers** that go beyond what current frameworks expose
- Developing rigorous **agent evaluation methodology**: how do you measure capability, reliability, and safety for systems that act in the world?

## Why This Portfolio

Most AI engineering knowledge is scattered across GitHub READMEs, blog posts, and Discord threads. I built this knowledge base because I needed a structured place to consolidate what I have learned from real projects — the architectural decisions, the failure modes, the benchmark numbers, and the reasoning behind trade-offs that are not obvious from documentation alone.

It is also a commitment device. Writing up a system forces precision in a way that building it does not. If I cannot explain clearly why a retrieval pipeline is chunked a certain way, or why a particular agent graph topology was chosen over an alternative, I probably do not understand it well enough yet.

This portfolio is a living document. It grows as I build, learn, and revise my understanding. The goal is not comprehensiveness — it is honesty about what I know, how I know it, and where the edges of my knowledge are.
