## 简介

我是 **Ding Guoliang**，一名 **AI 应用工程师**。工作落在模型能力与可上线软件之间：把大模型、检索、语音管线和 Agent 流程接到真实产品里，而不是停在 Demo。

过去半年多，我参与建设并打通了一套 **端侧语音 Agent 智控平台**（管理台 \+ 配置/业务后端 \+ 设备侧语音服务），功能已基本闭环并进入上线阶段。当前重点是把 AI 应用工程继续推向 **Agent 系统工程**；更远期目标是 **AI Runtime Engineer**。

本站记录我怎么想这些问题、在真实系统里做过什么取舍，以及还在学什么。

---

## 工程之路

```text
Java 后端开发
  → AI 应用工程
    → Agent 系统工程
      → AI Runtime Engineer（长期目标）
```

最早做 **Java 后端**，日常是可靠性、认证、权限和系统架构。这些习惯仍然决定我做 AI 的方式：不能只盯模型和框架，租户隔离、访问控制和生产约束一样重要。

进入 **AI 应用工程** 后，更多是在平台上搭应用、把助手能力做成可运营形态，并设计 **多租户 / 团队权限** 与配置下发。设备侧则要处理实时语音会话：VAD → ASR → LLM → TTS（以及端到端语音路径），并与工具调用、知识库检索协同。

接下来希望深入 **Agent 系统**：能规划、会调工具、能走多步任务。再往后，会往 **AI Runtime**——Agent 依赖的执行环境与基础设施——走。

## 工程理念

**生产优先于 Demo。** 关心能运营、能加固、能演进的系统。

**先弄清架构，再谈框架。** 检索、推理、会话、租户隔离和失败路径要心里有数。

**AI 能力要配上靠谱的软件工程。** 认证、权限、多租户和系统架构是产品工作的一部分。

**把学到的写下来。** 这个知识库用来沉淀判断、取舍和没想清楚的问题。
