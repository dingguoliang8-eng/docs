## Introduction

I am an AI Application Engineer. My work sits at the intersection of applied AI capabilities and production software systems — building applications that use large language models, retrieval, and agent-style workflows in ways that hold up beyond demos.

My current direction is clear: deepen AI application engineering into **Agent System Engineering**, with a longer-term goal of becoming an **AI Runtime Engineer**. This site documents how I think about those systems, what I am building, and what I am still learning.

---

## Engineering Journey

My path has been incremental rather than abrupt:

```text
Java Backend Development
  → AI Application Engineering
    → Agent System Engineering
      → AI Runtime Engineer (long-term goal)
```

I started in **Java backend development**, where reliability, authentication, permissions, and system architecture were everyday concerns. That foundation still shapes how I approach AI work: models and frameworks matter, but so do tenancy, access control, and production constraints.

As an **AI Application Engineer**, I have focused on building and evolving AI application platforms — taking existing AI capabilities and turning them into systems that can be deployed, shared, and operated. That includes transforming AI assistants into **SaaS-oriented** products and designing **multi-tenant** architectures around them.

Looking ahead, I am moving toward **Agent System Engineering**: systems that plan, use tools, and coordinate multi-step work rather than only answering single prompts. Longer term, I want to go deeper into **AI Runtime** — the execution environments and infrastructure that agent systems run on.

## Engineering Philosophy

Four principles guide how I work:

**Production over demos.** I care about systems that can be operated, secured, and evolved — not only prototypes that look good in a notebook.

**Understand the architecture, not only the framework.** Frameworks accelerate delivery, but I want a clear model of what sits underneath: retrieval, inference, tenancy, and failure modes.

**Combine AI with reliable software engineering.** Authentication, permissions, multi-tenant design, and system architecture are part of AI product work, not separate from it.

**Document what you learn.** This knowledge base exists so engineering judgment — including trade-offs and open questions — stays written down and revisable.
