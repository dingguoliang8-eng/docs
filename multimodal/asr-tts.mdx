语音正在变成人和 AI 交互的主入口。做好语音应用，要同时搞定两头：**ASR** 把用户说话变成文本，**TTS** 把模型回复变成自然语音。生产里更敏感的是延迟。

## ASR

常见选择：

- **Whisper**：开源基线，多语言、质量稳
- **FasterWhisper**：CTranslate2 重实现，速度大约快 4 倍，自托管生产更常用
- **Whisper.cpp**：偏 CPU / 边缘 / 隐私场景
- **OpenAI Whisper API**：省运维，适合中低流量和快速验证

自托管默认更推荐 FasterWhisper，并打开 VAD；但 VAD 阈值太猛会切掉真实语音头尾，上线前用真实音频测。

## TTS

- **OpenAI TTS**：声音稳定，可流式 PCM，多数产品默认够用
- **CosyVoice / FishSpeech**：开源，可克隆音色，中文场景常见
- **ElevenLabs**：自然度高，成本和延迟通常更高，更适合内容生成而非实时对话

实时场景不要等整段生成完再播：按句切分送 TTS，第一句就能先响。

## 语音 Agent 流水线

1. 采音（浏览器 WebRTC / 服务端 PyAudio）——建议 16kHz mono
2. VAD 判断说完
3. ASR 转写
4. LLM 流式生成（带历史）
5. 按句 TTS
6. 播放 PCM

## 延迟预算（目标端到端低于 500ms）

| 阶段 | 目标 |
| --- | --- |
| VAD | 低于 50ms |
| ASR | 低于 200ms（实时可用小模型） |
| LLM 首 Token | 低于 300ms |
| TTS 首包音频 | 低于 200ms |

模型常驻内存、按句播报、能并行的阶段就并行。全托管链路常见 800ms 到 1.5s，也能用，但对话感会差一截。
