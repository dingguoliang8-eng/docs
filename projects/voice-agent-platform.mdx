近半年与一位同事**共同建设**的代表项目：把「云端可运营的智控能力」和「设备侧实时语音 Agent」打成一条可上线闭环——管配置、下发策略、跑会话、调工具、查知识，而不是三个互不相干的 Demo。

我对全链路都熟悉（管理台、业务后端、设备侧语音服务），本文按**工程问题与取舍**来写，方便非本项目背景的读者读懂。案例已脱敏：不出现公司名、产品品牌、客户与内部细节。

---

## 一句话

做成一套 **控制面（智控台）\+ 会话面（设备侧语音服务）** 协同的平台：运营在网页里完成，实时对话在设备连接上完成；两边共享清晰的配置契约，并能演进。

---

## 要解决什么问题

端侧语音要低延迟、能打断、会话稳定；云端又要管设备、智能体、模型、知识库和团队权限。若两边各干各的，常见后果是：

- 现场只能改本地文件，无法按设备统一运营
- 助手停在「能答一句」，接不上工具与知识库
- 权限边界含糊：能登录后台 ≠ 数据隔离正确

目标不是再做一个 Demo Agent，而是**可部署、可运营、可降级**的闭环。

## 系统怎么拆

```text
智控台前端 (Vue)
    ↕ HTTP
智控台后端 (Java / Spring)
  · 设备 / 智能体 / 模型 / 知识库
  · 认证与团队数据隔离
  · 向设备侧下发「按设备」的配置
    ↕ 配置拉取（服务身份鉴权，与用户登录分离）
设备侧语音服务 (Python)
  · WebSocket 会话（一设备一连接）
  · 经典：VAD → ASR → LLM → TTS
  · 或：端到端语音路径（与经典路径二选一）
  · 工具 / 插件 / MCP 统一调度
```

## 分工怎么理解（双人共建）

项目由**两人共同推进**，我日常覆盖三层，能独立讲清任意一段的设计与联调问题：

| 层 | 我们一起做的事（摘要） |
| --- | --- |
| 智控台前端 | 管理界面、权限相关交互、业务 API 多区域切换 |
| 智控台后端 | 设备/智能体/模型/知识库、系统权限与团队隔离、配置下发 |
| 设备侧服务 | 会话主路径、语音管线装配、工具调度、与控制面配置协同 |

写作上不写成「我一个人独立主导全栈」，也不缩成「只摸过边角」——更准确的说法是：**全链路共建，我对整体设计与落地都清楚。**

## 五个关键取舍（人话版）

### 1. 配置：既要统一运营，又要能本地调试

**问题：** 只靠本地文件，运维管不住；只靠云端下发，开发联调又太慢。

**做法：**

- 有控制面时，以云端基座配置为主，建连后再按设备拉差异配置
- 默认可提交的结构与密钥/现场覆盖分开，密钥不进默认模板
- 保留少量「本地可覆盖」项，方便现场排障或灰度换模块，而不必改整套控制面

**原则：** 契约字段两边一致；改契约就双边同步，避免「改一份 YAML 再改一套 API」。

### 2. 语音主路径：经典管线与端到端，只能走一条

**问题：** 同时开「级联 ASR→LLM→TTS」和「端到端语音模型」，很容易抢音频、抢状态。

**做法：** 同一连接只激活一条主路径。经典路径按阶段可插拔装配；端到端走独立桥接层，处理打断、半双工与工具生命周期。默认仍以经典路径可运行为前提扩能力。

### 3. 扩展方式：核心会话要瘦，能力往外挂

**问题：** 新协议、新工具都往连接主类里堆，几个月后没人敢改。

**做法：**

- 设备文本消息按类型路由到独立处理逻辑
- 新模型/语音能力优先做成可替换模块
- 工具来源（服务端插件、MCP、设备侧能力等）收成统一目录再分发

这样「能说话」可以稳定升级成「能办事」，而不用重写会话核心。

### 4. 打断：上一轮必须死干净

**问题：** 用户打断后，旧的生成/播报/字幕还在飞，会出现「幽灵播报」。

**做法：** 用轮次标记作废过期输出；阻塞型初始化与重计算放进线程池，避免卡住收发包循环；非关键预热（如记忆）不挡首轮交互。

对语音产品，这比「模型更聪明一点」更影响体感。

### 5. 权限：菜单权限 ≠ 数据隔离

**问题：** 只做登录和菜单，多团队场景会串数据。

**做法：**

- **系统层**：谁能进哪些功能
- **团队层**：谁能碰哪些业务资源；写操作必须带明确团队上下文
- 列表/检索在查询侧强制范围，而不是只靠前端藏按钮
- 前端团队上下文由业务调用显式携带，避免全局隐式头写错队

## 失败时怎么办（降级意识）

上线前更关心「坏的时候像什么」，而不是只演示 Happy Path：

| 情况 | 期望行为（产品语义） |
| --- | --- |
| 设备未绑定 / 拉配置失败 | 进入受限引导态，而不是连接直接被踢死 |
| 某一语音合成实现不可用 | 有占位回落，管线仍能起来 |
| 知识检索超时或失败 | 短超时；失败信息可理解，不拖死整轮对话 |
| 长耗时工具进行中用户打断 | 工具生命周期收尾，界面不会一直转圈 |
| 控制面瞬时故障 | 拉配置有限重试；本地模式仍可独立开发 |

更细的坑与复盘见 [经验总结](/notes/lessons-learned)。

## 知识库怎么进对话

控制面负责知识与模型的运营配置；对话里按需检索，而不是把检索写死在语音主循环里。多团队场景下，知识资源与业务数据一样要带隔离范围。

（站内 [RAG](/rag/overview) 章节是通用方法对照；本项目主路径是「智控配置 \+ 会话内工具检索」。）

---

## 可观测性：按连接排障

没有「这一通会话用了哪套模块、卡在哪一段」，线上只能重启。实践上：

- 日志按模块打标签，并带上设备/会话上下文
- 能看出当前装配了哪些语音/模型组合
- 配置类日志脱敏后再落盘

目标不是堆监控大盘名词，而是**偶现问题可复盘**。
